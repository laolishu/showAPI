# Swagger / OpenAPI 文档转换工具：MVP 验收标准与路线图（框架）

> 文档状态：草案  
> 版本：0.1  
> 最后更新：2026-08-25

## 1. 版本目标

MVP 验证核心价值：用户无需部署后端或上传敏感文档，即可将一份常规 Swagger/OpenAPI 文件转换为可使用的 Word 文档。

## 2. MVP 验收标准

| 编号 | 验收项 | 可验证标准 |
| --- | --- | --- |
| AC-01 | JSON 导入 | 可导入并解析合法 Swagger 2.0、OpenAPI 3.0 JSON 文件。 |
| AC-02 | YAML 导入 | 可导入并解析合法 Swagger 2.0、OpenAPI 3.0 YAML 文件。 |
| AC-03 | 本地处理 | 断网后，本地文件导入、解析、导出仍可工作；不上传源文档。 |
| AC-04 | 解析预览 | 显示标题、版本、接口数、Tag 数、Schema 数及错误信息。 |
| AC-05 | 内容筛选 | 可选择全部接口或按 Tag 筛选导出。 |
| AC-06 | Word 导出 | `.docx` 可在 Word/WPS 打开，中文、标题和参数表正常。 |
| AC-08 | 错误提示 | 非法格式、解析异常、未识别的版本有可理解提示，且不生成误导性文档。 |
| AC-09 | 复杂引用 | 至少能处理常见 `$ref`；循环引用不会造成页面卡死或无限输出。 |
| AC-10 | 性能 | 10 MB 以内、300 个接口以内的规范在目标浏览器中可完成导出，页面不崩溃；超阈值时预览降级为前 50 个接口 + "加载更多"，导出前提示预计耗时，不强制阻断。 |

## 3. MVP 交付范围

### 必须完成

- 输入与基础校验。
- Swagger 2.0 / OpenAPI 3.0 适配至统一 IR。
- 默认模板（可填写项目名称）的 Word 导出。
- 基础预览、Tag 筛选、下载与错误反馈。
- 关键样例文件和自动/手动验证记录。

### 可选完成

- Web Worker 性能优化。
- 请求与响应示例展示开关。

### 不在 MVP

- 云端账号、协作和文档存储。
- 编辑 OpenAPI 内容。
- 批量合并、多格式输入、可视化模板设计器。
- PDF、Logo、主题色与 OpenAPI 3.1 兼容。

## 4. 路线图

| 阶段 | 目标 | 主要产物 |
| --- | --- | --- |
| P0：方案冻结 | 统一 MVP 产品边界与技术可行性 | 本 `docs` 文档包、技术选型结论 |
| P1：核心链路 | 跑通导入、解析、IR、Word | 可运行的本地前端原型 |
| P2：完整 MVP | 加入筛选、预览、错误处理与验收 | 可验收 MVP 和样例导出文件 |
| P3：体验增强 | PDF、模板配置、性能、OpenAPI 3.1 | V1.1 版本 |
| P4：产品扩展 | 批量、更多格式、离线桌面化 | V2 候选能力 |

## 5. 上线前最低验证集

- Swagger 2.0 JSON：含路径参数、查询参数、模型引用。
- Swagger 2.0 YAML：含数组、枚举、嵌套对象。
- OpenAPI 3.0 JSON：含 `requestBody`、多个响应和服务器地址。
- OpenAPI 3.0 YAML：含 `allOf`、`oneOf` 或 `anyOf` 的代表性样例。
- 中文接口描述与字段名样例。
- 约 100 个接口的性能样例。
- 非法 JSON/YAML、缺失版本字段、无 `paths` 的异常样例。

## 6. 阶段完成定义（Definition of Done）

一个阶段只有在以下条件同时满足时才可标记完成：

1. 对应任务清单全部完成或明确延期原因。
2. 对应验收项有可复现的验证记录。
3. 核心样例可成功生成目标文档。
4. 已知限制已写入用户可见的提示或项目文档。
