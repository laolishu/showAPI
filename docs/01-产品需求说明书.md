# Swagger / OpenAPI 文档转换工具：产品需求说明书（框架）

> 文档状态：草案  
> 版本：0.1  
> 最后更新：2026-08-25

## 1. 产品定位

一个在浏览器本地运行的工具，将 Swagger 2.0 与 OpenAPI 文档转换为可交付的 Word 文档；PDF 作为后续版本能力。用户的 API 文档不上传至服务端。

## 2. 目标与价值

- 降低 API 文档归档、评审、对外交付的整理成本。
- 用 Word 提供便于阅读和打印的接口说明。
- 以纯前端实现保障数据本地处理、即开即用和低运维成本。

## 3. 目标用户与场景

| 用户 | 场景 | 主要产物 |
| --- | --- | --- |
| 开发人员 | 接口评审、联调、对外交付 | Word |
| 测试人员 | 接口盘点、测试用例准备 | Word |
| 项目经理/文档人员 | 项目归档、审阅、交付留痕 | Word |

## 4. MVP 用户流程

1. 用户上传、拖拽或粘贴 Swagger / OpenAPI 的 JSON、YAML 内容。
2. 系统在浏览器本地校验并解析文档。
3. 系统展示 API 基本信息、接口数量、Tag 分组和解析错误。
4. 用户选择全部接口或按 Tag 筛选导出范围。
5. 用户选择 Word 并生成下载文件。

## 5. MVP 功能范围

### 5.1 包含

- 本地文件上传、拖拽上传、JSON/YAML 文本粘贴。
- Swagger 2.0、OpenAPI 3.0 的基础解析。
- 接口、参数、请求体、响应、Schema、Tag 的解析与预览。
- 按 Tag 筛选导出。
- 默认模板（可填写项目名称）的 Word 导出。
- 解析失败、格式不支持和生成失败的明确提示。
- 本地处理，不上传 API 文档内容。

### 5.2 暂不包含

- 在线账号、云端存储、团队协作。
- 编辑或修复 Swagger/OpenAPI 源文档。
- 任意远程 URL 拉取（受浏览器跨域限制）。
- 多个 API 文档的智能合并。
- 可视化拖拽模板编辑器。
- 非 Swagger/OpenAPI 格式的直接导入。
- PDF 导出；该能力列入后续版本，不作为 MVP 交付或验收项。

## 6. 关键产品规则

- 导入文件和解析结果仅驻留在当前浏览器会话；用户主动保存的模板偏好可存于本地浏览器。
- 导出前必须展示解析结果与错误信息；存在不可恢复错误时禁止导出。
- Word 重视完整阅读体验与结构化表达。
- 复杂 Schema 的展示必须避免无限递归，并保留引用关系的可理解说明。

## 7. 已确认的 MVP 决策

| 编号 | 决策 | 已确认结论 |
| --- | --- | --- |
| R1 | 规范支持范围 | 正式支持 Swagger 2.0 与 OpenAPI 3.0；OpenAPI 3.1 不纳入 MVP 验收。 |
| R2 | PDF 交付标准 | PDF 不纳入 MVP，后续版本再评估并完成技术验证。 |
| R3 | 品牌信息与模板 | 使用默认模板，并支持填写项目名称；Logo、主题色等留待后续版本。 |
| R4 | 导出范围 | 支持导出全部接口或按 Tag 多选；不支持逐接口勾选。 |
| R5 | 文档内容深度 | 输出接口核心信息、参数、请求体、响应、Schema 和示例；安全与服务器环境信息为可选章节。 |
| R6 | 文件处理方式 | MVP 一次仅处理一份 API 文档。 |

## 8. 成功指标（MVP）

- 用户可在无需后端服务的条件下完成一次有效文档转换。
- 生成的 Word 能被主流办公软件正常打开。
- 常规规模（约 100 个接口）的文档转换不导致浏览器页面崩溃。
- 导出内容能覆盖接口路径、方法、参数、请求体、响应与数据模型等核心信息。
