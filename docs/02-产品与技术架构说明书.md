# Swagger / OpenAPI 文档转换工具：产品与技术架构说明书（框架）

> 文档状态：草案  
> 版本：0.1  
> 最后更新：2026-08-25

## 1. 架构目标

- 全程在浏览器运行，不依赖业务后端。
- 解析逻辑与 Word、PDF 的生成逻辑解耦。
- 支持后续新增导出格式和模板能力。
- 对大文件、复杂 `$ref`、循环引用提供可控的降级与错误反馈。

## 2. 总体架构

```text
界面层
  导入与校验 | 解析预览 | 导出范围选择 | 模板配置 | 进度与错误提示

领域层
  规范适配器 -> 统一 API 中间模型（IR） -> 文档内容组织器 -> 格式渲染器

基础设施层
  文件读取 | YAML/JSON 解析 | Web Worker | 本地配置 | 文件下载 | 字体资源
```

## 3. 核心模块与职责

| 模块 | 职责 | MVP 要点 |
| --- | --- | --- |
| 输入模块 | 读取文件和粘贴文本，识别格式 | 限制文件类型、大小并提供提示 |
| 规范适配器 | 将 Swagger 2.0 / OpenAPI 3.x 转为统一数据 | 隔离版本差异 |
| 引用解析器 | 解析 `$ref`、组合 Schema 和循环引用 | 最大展开深度、循环保护 |
| IR 构建器 | 生成格式无关的 API 文档模型 | 作为唯一渲染输入 |
| 内容组织器 | 按导出规则组织目录、接口、模型 | 支持 Tag 筛选 |
| Word 渲染器 | 把内容转换为 `.docx` | 表格、标题层级、分页 |
| PDF 渲染器 | 把内容转换为 `.pdf` | 后续版本模块，不属于 MVP |
| 下载服务 | 使用 Blob 触发浏览器下载 | 统一文件命名与错误处理 |

## 4. 统一 API 中间模型（IR）

IR 是解析与导出之间的唯一契约。Swagger 2.0 与 OpenAPI 3.0 的差异必须在适配层消化；Word 渲染器不得直接读取原始规范。

```text
ApiDocument
├─ info：标题、版本、描述、联系人、许可证、规范版本
├─ servers：服务地址
├─ tags：模块名称和描述
├─ operations：标准化接口列表
└─ schemas：可复用数据模型
```

### 4.1 核心实体契约

| 实体 | 必填字段 | 说明 |
| --- | --- | --- |
| `ApiDocument` | `info`、`sourceVersion`、`operations`、`schemas` | 一份导入文档对应一个 IR 根对象。 |
| `ApiInfo` | `title`、`version` | 可选保留 `description`、`contact`、`license`。 |
| `ApiTag` | `name` | 可选保留 `description`。 |
| `ApiOperation` | `operationKey`、`method`、`path`、`displayName`、`primaryTag`、`parameters`、`responses` | 一个 HTTP 方法与路径的组合对应一条接口。 |
| `ApiParameter` | `name`、`location`、`type`、`required` | 表示非请求体参数，位置为 `path`、`query`、`header` 或 `cookie`。 |
| `ApiRequestBody` | `content` | `content` 按 Content-Type 保存请求体 Schema、字段树和示例。 |
| `ApiResponse` | `statusCode`、`description`、`content` | 一个状态码对应一个响应对象；必须保留所有状态码。 |
| `ApiField` | `name`、`path`、`depth`、`type` | 可用于请求体、响应体和数据模型；以树形 `children` 表达嵌套结构。 |
| `ApiSchema` | `name`、`rootField` | 表示可复用的 Schema 定义及其字段树。 |

### 4.2 `ApiOperation` 的冻结规则

| 规则 | 已确认结论 |
| --- | --- |
| 唯一键 | `operationKey` 固定为 `METHOD + 空格 + PATH`，例如 `GET /api/users/{id}`。 |
| 显示名称 | `summary` 优先，其次 `operationId`，最后为 `METHOD + PATH`。 |
| 原始标识 | `operationId` 原样保存，可为空；不作为唯一键。 |
| 分组 | 第一个 Tag 为 `primaryTag`；没有 Tag 时使用“未分组”。 |
| 排序 | 先按 `primaryTag`，再按 `path`，最后按 HTTP 方法排序；渲染层可按该稳定顺序输出。 |
| 弃用标记 | 原规范 `deprecated` 为真时写入 `deprecated: true`。 |

### 4.3 `ApiField` 的冻结规则

每个字段节点必须具备以下属性：

| 字段 | 含义 |
| --- | --- |
| `name` | 当前层字段名。 |
| `displayIndex` | 用于 Word 的层级编号，例如 `2.3.1`。 |
| `path` | 语义字段路径，例如 `data.records[].customsCode`。 |
| `parentPath` | 父级语义路径；根字段为空。 |
| `depth` | 从根开始的层级深度；Word 缩进由此计算。 |
| `location` | `path`、`query`、`header`、`cookie`、`body` 或 `response`。 |
| `type` / `format` | 标准化类型与可选格式。 |
| `required` | 是否必填；对象字段由所属对象的 `required` 列表推导。 |
| `description` | 原规范描述；缺失时为空。 |
| `defaultValue` / `enumValues` | 默认值与枚举选项。 |
| `example` / `exampleSource` | 示例值与来源：`explicit`、`default`、`derived`、`none`。 |
| `referenceName` | `$ref` 或模型引用名称；没有则为空。 |
| `children` | 嵌套对象或数组元素字段。 |

类型文本统一为 `string`、`integer<int64>`、`number<double>`、`boolean`、`object<模型名>`、`array<元素类型>`；未知类型保留原始类型文本并标记为未标准化。

### 4.4 引用、组合 Schema 与展开规则

| 场景 | 已确认规则 |
| --- | --- |
| `$ref` | 可安全解析时展开为字段树，并保留 `referenceName`。 |
| 循环引用 | 通过访问栈识别，停止展开并保存“循环引用已停止展开”提示。 |
| 最大深度 | 默认最大展开深度为 `8`；超过时停止展开并保存“已达到最大展开深度”提示。 |
| `allOf` | 合并可确定的字段。 |
| `oneOf` / `anyOf` | 不强行合并；保留组合类型与候选模型名称。 |
| 数组 | 父字段自身作为一行，类型为 `array<元素类型>`；数组元素字段放在 `children`。 |

### 4.5 响应与示例规则

- 所有已定义响应码均写入 `ApiOperation.responses`，包括错误响应。
- `primaryResponse` 用于 Word 的“返回属性名”、响应字段表和默认响应示例：优先选择 `200`，其次选择其他 `2xx`，均不存在时选第一个已定义响应并标记为非成功响应。
- 示例只来自规范中的 `example`、`examples`、`default`，或按类型生成的明确标记占位值；不得发起真实 HTTP 请求。
- IR 不保存 Word 的缩进像素等格式信息；这些由渲染器负责。

### 4.6 解析流程与 `$ref` 安全边界

```text
本地文件或粘贴文本
  → 使用 `yaml` / JSON 读取为对象
  → 使用 `@apidevtools/swagger-parser` 校验 Swagger 2.0 / OpenAPI 3.0 规范
  → 保留原始规范对象与校验诊断
  → 自有适配器解析内部 `#/...` 引用并构建无循环 IR
  → Word 渲染器消费 IR
```

| 项目 | MVP 规则 |
| --- | --- |
| 解析库职责 | `@apidevtools/swagger-parser` 负责规范校验、JSON/YAML 解析能力和引用诊断辅助。 |
| IR 构建 | 自有适配器处理原始规范与内部引用，不把 `dereference()` 结果直接作为 IR 输入。 |
| 本地引用 | 支持同一份文档中的 JSON Pointer，例如 `#/definitions/User`、`#/components/schemas/User`。 |
| 外部引用 | 禁止文件路径及 HTTP/HTTPS URL `$ref`；解析时不访问本地磁盘、网络或携带凭据。 |
| 外部引用提示 | 检测到外部 `$ref` 时，提示“当前 MVP 仅支持单文件内部引用”。 |
| 循环引用 | 依照最大 8 层展开规则降级，不让循环对象进入 Word 或 `JSON.stringify()` 流程。 |

## 5. 关键技术原则

- **本地优先**：不发送源文档到网络；无需账号或 API 密钥。
- **适配器隔离**：Swagger 2.0 与 OpenAPI 3.x 差异只能存在于适配器内部。
- **渲染器独立**：各格式渲染器只消费 IR 和导出配置，不直接读取原始规范。
- **失败可见**：无法解析或无法生成时给出位置、原因和可操作建议。
- **性能保护**：大文档解析可迁移到 Web Worker；预览使用分页或虚拟列表。

## 7. 主要风险与处理方向

| 风险 | 处理方向 |
| --- | --- |
| CJK 中文字体/PDF 文本可复制 | 后续 PDF 版本开始前完成 PoC 并记录结论 |
| `$ref` 循环引用 | 使用访问栈与最大深度保护，显示引用提示 |
| `allOf` / `oneOf` / `anyOf` | 明确保留组合关系还是展开合并的展示规则 |
| 大规格文件卡顿 | Worker 解析、懒加载预览、限制导出提示 |
| 浏览器内存限制 | 设定文件大小和接口数量建议阈值 |
